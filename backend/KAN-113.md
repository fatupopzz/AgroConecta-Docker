# KAN-113 — Calendario de cultivo (backend)

Contrato de la API para la parte Android (KAN-114). Los ejemplos salen de una
prueba real contra PostgreSQL con la migración aplicada.

## Reglas generales

- Todas las rutas van bajo `/api/plantings` y piden `Authorization: Bearer <JWT>`.
- `templates` lo puede leer cualquier usuario autenticado. `mine`, `POST` y
  `PATCH` son solo para `tipo = agricultor`; otro rol recibe `403`.
- Los errores tienen siempre la forma `{ "error": "mensaje para mostrar" }`.
- Fechas de calendario (`fecha_siembra`, `fecha_programada`): texto
  `YYYY-MM-DD`, sin hora ni zona. Se muestran tal cual; no hay que convertirlas
  de zona horaria.
- Instantes (`fecha_creacion`, `fecha_hecha`): ISO 8601 en UTC, por ejemplo
  `2026-10-16T17:38:26.267Z`.
- `tipo` de tarea: `sembrar`, `fertilizar`, `fumigar`, `deshierbar`,
  `cosechar` u `otro`. Conviene que la app tenga un ícono por defecto para
  valores nuevos.
- `categoria_sugerida` puede ser `null`. Si viene, `id_categoria` sirve para
  abrir el catálogo filtrado: `GET /api/products?id_categoria=<id>`.

## GET /api/plantings/templates

Cultivos para el selector. Responde `200` con un arreglo ordenado por nombre.

```json
[
  {
    "id_plantilla": 2,
    "cultivo": "frijol",
    "nombre": "Frijol",
    "descripcion": "Frijol de grano, unos 85 días desde la siembra hasta el arranque.",
    "duracion_dias": 85,
    "tareas": [
      {
        "nombre": "Siembra",
        "tipo": "sembrar",
        "dia_desde_siembra": 0,
        "categoria_sugerida": { "id_categoria": 4, "nombre": "Semillas" }
      },
      {
        "nombre": "Fertilización inicial",
        "tipo": "fertilizar",
        "dia_desde_siembra": 10,
        "categoria_sugerida": { "id_categoria": 1, "nombre": "Fertilizantes" }
      }
    ]
  }
]
```

- `cultivo` es el valor que hay que mandar en el `POST`. `nombre` es el texto
  para mostrar, por ejemplo `"Maíz (elote)"`.
- `duracion_dias` es el día de la última tarea; sirve para mostrar "unos 85 días".
- Cultivos iniciales: `maíz`, `frijol`, `tomate` y `papa`. En el tomate los
  días se cuentan desde el trasplante, como dice su `descripcion`.

## POST /api/plantings

Registra una siembra y genera su calendario.

```json
{ "cultivo": "maíz", "fecha_siembra": "2026-10-06" }
```

- `cultivo` acepta mayúsculas y sin tilde (`"Maiz"`, `"MAIZ"`), pero lo más
  seguro es mandar el `cultivo` que vino en `templates`.
- `fecha_siembra` tiene que existir en el calendario (no `2026-02-30`) y estar
  como máximo un año antes o después de hoy, en hora de Guatemala.
- Cada tarea se programa en `fecha_siembra + dia_desde_siembra`.

Responde `201` con la siembra creada, con la misma forma que cada elemento de
`GET /mine`:

```json
{
  "id_siembra": 1,
  "id_plantilla": 1,
  "cultivo": "maíz",
  "nombre_cultivo": "Maíz (elote)",
  "fecha_siembra": "2026-10-06",
  "fecha_creacion": "2026-10-16T17:38:26.239Z",
  "tareas": [
    {
      "id_tarea": 1,
      "nombre": "Siembra",
      "tipo": "sembrar",
      "fecha_programada": "2026-10-06",
      "categoria_sugerida": { "id_categoria": 4, "nombre": "Semillas" },
      "hecha": false,
      "fecha_hecha": null
    },
    {
      "id_tarea": 2,
      "nombre": "Primera fertilización (NPK)",
      "tipo": "fertilizar",
      "fecha_programada": "2026-10-16",
      "categoria_sugerida": { "id_categoria": 1, "nombre": "Fertilizantes" },
      "hecha": false,
      "fecha_hecha": null
    }
  ]
}
```

Errores:

| Código | Cuándo | `error` |
|---|---|---|
| 400 | Falta el cultivo o no es texto válido | `Debes indicar un cultivo válido` |
| 400 | Cultivo sin plantilla (por ejemplo `café`) | `No hay calendario disponible para ese cultivo` |
| 400 | Fecha con otro formato o que no existe | `fecha_siembra debe ser una fecha válida con formato YYYY-MM-DD` |
| 400 | Fecha a más de un año de hoy | `fecha_siembra debe estar dentro de un año antes o después de hoy` |
| 403 | El usuario no es agricultor | `El calendario de cultivo solo está disponible para agricultores` |

## GET /api/plantings/mine

Siembras del agricultor autenticado, de la más reciente a la más antigua según
`fecha_siembra`. Dentro de cada siembra, las tareas vienen ordenadas por
`fecha_programada`. Responde `200` con un arreglo de objetos con la misma forma
que la respuesta del `POST`, o `[]` si no tiene siembras.

Las tareas de fechas pasadas siguen apareciendo, hechas o no. La app decide
cómo marcarlas (atrasada, hecha, de hoy, próxima).

## PATCH /api/plantings/tasks/:id

Marca o desmarca una tarea como hecha.

```json
{ "hecha": true }
```

`hecha` tiene que ser booleano: `"true"` como texto se rechaza. Responde `200`:

```json
{ "id_tarea": 2, "id_siembra": 1, "hecha": true, "fecha_hecha": "2026-10-16T17:38:26.267Z" }
```

- Al desmarcar, `fecha_hecha` vuelve a `null`.
- Volver a marcar una tarea que ya estaba hecha conserva su `fecha_hecha` original.
- Desmarcar una tarea no hace que se vuelva a notificar.

| Código | Cuándo | `error` |
|---|---|---|
| 400 | `:id` no es un entero positivo | `id de tarea inválido` |
| 400 | `hecha` falta o no es booleano | `hecha debe ser true o false` |
| 403 | La tarea es de otro agricultor | `No puedes modificar tareas de una siembra que no es tuya` |
| 403 | El usuario no es agricultor | `El calendario de cultivo solo está disponible para agricultores` |
| 404 | La tarea no existe | `Tarea no encontrada` |

## Notificación push del día

Cada día, a partir de las 7:00 en hora de Guatemala, el backend manda un push
por cada tarea de ese día que no esté hecha. Cada tarea se avisa una sola vez.

- **Token:** se usa el mismo token FCM que la app ya registra para las alertas
  de plaga (`POST /api/alerts/pests/installations`), con la misma regla de que
  el registro tenga menos de 90 días. Si el agricultor no registró su teléfono,
  no recibe el aviso. El calendario igual funciona.
- **Mensaje:** trae `notification` para que el sistema lo muestre con la app
  cerrada, y `data` para abrir la tarea:

```json
{
  "notification": {
    "title": "Tarea de tu calendario de cultivo",
    "body": "Maíz (elote): Primera fertilización (NPK)"
  },
  "data": {
    "type": "planting_task",
    "task_id": "2",
    "planting_id": "1",
    "task_type": "fertilizar",
    "crop": "Maíz (elote)"
  }
}
```

Con la app en primer plano, Android entrega el mensaje a `onMessageReceived`.
Hoy `PestAlertMessagingService` lo descarta, porque `PestAlertPushPayload.from`
devuelve `null` para cualquier tipo que no sea `pest_alert` o `alerta_plaga`.
KAN-114 tiene que manejar también `planting_task`. Los valores de `data`
siempre llegan como texto.

## Notas para el despliegue

- Migración: `backend/sql/016_kan113_calendar.sql`. Es idempotente y no
  corre al arrancar el backend; hay que aplicarla a mano antes del rebuild.
- Variables opcionales del scheduler:
  - `PLANTING_REMINDERS_HOUR`: hora local desde la que se avisa. Por defecto `7`.
  - `PLANTING_REMINDERS_INTERVAL_MS`: cada cuánto revisa. Por defecto 15 minutos, mínimo 1 minuto.
- Sin `FIREBASE_SERVICE_ACCOUNT_BASE64`, el scheduler no hace nada; el resto
  del calendario funciona igual.
- Las tareas de fungicida sugieren la categoría `Fungicidas` si la base la
  tiene, y si no, `Pesticidas`.
- No reemplaza a `GET /api/ciclos/:cultivo` (HU-026). Ese es un calendario
  nacional por meses; este es el calendario de una siembra concreta con fechas.
